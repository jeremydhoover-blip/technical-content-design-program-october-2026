# Grammar and Style: Luma

> **Worked example.** This is a finished file for Luma, a fictional team workflow app. Read it to see what done looks like. Write your own for your product instead of copying this one.

This file defines writing conventions for Luma. Apply these rules consistently across UI strings, documentation, and any content generated for or about the product.

---

## Voice fundamentals

- Write in active voice. "Save your changes" not "Changes will be saved."
- Use second person ("you," "your") to address users directly.
- Be direct. Skip filler openers like "Please note that..." or "It is important to..."
- Use present tense for states and status. "Your file is uploading." not "Your file will be uploading."
- Use imperative voice for calls to action. "Add a project." not "You can add a project."

---

## Punctuation

**Periods:** Use periods in body copy and multi-sentence helper text. Omit periods on single-sentence labels, button text, and short standalone headings.

**Commas:** Use the Oxford comma in lists of three or more items.

**Colons:** Use a colon to introduce a list or to label a field value. Don't use a colon at the end of a label that sits above an input ("Name" not "Name:").

**Ellipsis:** Use `...` (a real ellipsis character, not three periods) only for truncated text or in-progress states ("Loading..."). Don't use it to trail off in copy.

**Em dashes:** Avoid. Rewrite to use a comma, period, or new sentence.

**Exclamation points:** Use sparingly. One per page maximum, only in genuinely celebratory moments (completing onboarding, first meaningful milestone). Not in errors, labels, or routine confirmations.

**Quotation marks:** Use straight quotes in UI copy. Reserve curly/smart quotes for long-form documentation.

---

## Capitalization

**Sentence case everywhere.** Headlines, buttons, labels, nav items, tab names, and menu items are all sentence case.

- "Add new project" not "Add New Project"
- "Sign in" not "Sign In"
- "Delete account" not "Delete Account"

**Proper nouns and product names are always capitalized** per their official styling.

**Feature names:** Treat feature names as common nouns, not proper nouns, unless they are officially branded. Write "the dashboard" not "the Dashboard."

---

## Numbers and dates

**Numbers:** Spell out one through nine. Use numerals for 10 and above, and always for measurements, quantities in UI labels, and technical values.

**Dates:** Use `Month D, YYYY` for full dates (July 6, 2026). In dense UI contexts, use `MMM D` (Jul 6). Avoid ambiguous formats like `07/06/26`.

**Time:** Use 12-hour format with lowercase am/pm and a space before it (2:30 pm). Include the timezone if it's relevant to the user's context.

**Percentages:** Use the % symbol with no space (42%).
